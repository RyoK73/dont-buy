# Don't Buy — 機能・技術設計

コンセプトの詳細は [README.md](../README.md) を参照。本ドキュメントは、コンセプトを実際のWebアプリに落とし込むための機能設計・技術設計をまとめたもの。

## データモデル

3テーブル構成。全て Row Level Security (RLS) で `user_id = auth.uid()` の行のみ読み書き可能にする。

### `users`

Supabase Auth の `auth.users` をそのまま利用する（アプリ独自の `users` テーブルは作らない）。メール＋パスワード認証と匿名認証（ゲストログイン）の両方を同じテーブルで扱える。

### `goals`（目標商品）

| カラム         | 型          | 説明                                  |
| -------------- | ----------- | ------------------------------------- |
| `id`           | uuid        | PK                                    |
| `user_id`      | uuid        | FK → `auth.users.id`                  |
| `name`         | text        | 商品名（必須）                        |
| `price`        | integer     | 価格（必須、円）                      |
| `url`          | text        | 購入先リンク（任意）                  |
| `purchased_at` | timestamptz | 購入済みになった日時（null = 未購入） |
| `created_at`   | timestamptz | 登録日時                              |

### `savings_entries`（我慢履歴）

| カラム       | 型          | 説明                       |
| ------------ | ----------- | -------------------------- |
| `id`         | uuid        | PK                         |
| `user_id`    | uuid        | FK → `auth.users.id`       |
| `amount`     | integer     | 我慢した金額（必須、円）   |
| `category`   | text        | カテゴリ（任意、null許容） |
| `memo`       | text        | メモ（任意、null許容）     |
| `created_at` | timestamptz | 登録日時                   |

### 貯金プールの考え方

`savings_entries` にテーブル自体は「プール残高」を持たない。プール残高は都度計算で導出する。

```
プール残高 = SUM(savings_entries.amount) - SUM(goals.price WHERE purchased_at IS NOT NULL)
```

目標が複数ある場合も配分ロジックは持たず、同じプール残高をすべての未購入 `goals` に対して比較する。

```
達成度% (goal) = MIN(100, プール残高 / goal.price * 100)
```

商品を実際に購入した（`purchased_at` をセットした）タイミングで、上の計算式が自動的にプール残高から購入額を差し引く形になる。専用の「差し引きトランザクション」テーブルは持たない。

## 画面構成・ルーティング

Next.js App Router の別ルートとして実装する。

- `/dont-buy` — 我慢登録UI（金額必須・カテゴリ任意・メモ任意の最小入力フォーム）＋ 節約履歴一覧（統計含む）
- `/buy` — 目標商品一覧（それぞれの達成度%をゲージ表示）＋ 目標商品の登録・編集・削除
- 両モードはワンボタンで相互に遷移する導線を用意し、**View Transitions API**（Next.js 16 の `experimental.viewTransition`）でモード切替時にフェード/スライドのアニメーションを付ける。

### 統計UI（MVP範囲）

- 今月の節約合計金額
- 節約履歴のリスト表示（日付・金額・メモ）
- グラフ表示やカテゴリ別集計はMVP対象外

### モチベーション表示

「目標日への到達予測」ではなく、達成度%ベースで表現する。

- 「今月 ○○円節約しました」
- 「今日/今週/今月の行動で目標に x% 近づきました」← 期間の開始時点と現在の達成度%の差分を表示するだけで、新規の予測ロジックは不要。

## 認証

- Supabase Auth の **メール＋パスワード** をメイン認証方式とする。
- ポートフォリオ閲覧用の**ゲストログイン**は Supabase の**匿名認証**（`signInAnonymously()`）で実装する。定期的な匿名ユーザーのクリーンアップ運用を検討する。

## 技術選定

| ジャンル                 | 技術                                            |
| ------------------------ | ----------------------------------------------- |
| フロントエンド           | Next.js 16 (App Router) / React 19 / TypeScript |
| スタイリング             | Tailwind CSS v4 + shadcn/ui                     |
| ルート遷移アニメーション | View Transitions API                            |
| バックエンド             | Next.js (Server Actions / Route Handlers)       |
| DB・認証                 | Supabase (PostgreSQL, Supabase Auth)            |
| デバイス対応             | レスポンシブWebのみ（PWA化はスコープ外）        |

## MVPスコープ

### やる

- 我慢登録（金額必須＋カテゴリ任意＋メモ任意）
- 目標商品のCRUD（商品名＋価格＋URL任意）
- BUY / Don't Buy モードの切り替えとそれぞれの画面
- 共有プールによる達成度%計算・購入時の差し引き
- 月別合計・履歴リストの統計表示
- メール＋パスワード認証、匿名ゲストログイン
- 複数目標の同時登録（無制限・無料）

### やらない（将来の拡張候補）

- 課金・目標登録数の上限設定
- 目標到達日の予測表示
- カテゴリ別集計・グラフ表示
- 商品画像のアップロード
- PWA化
